## Content model

`logo`, `brandLabel`, and `copyright` come from the shared `footerFields` base that every Footer
variant spreads; `links` is specific to this variant. The row wraps rather than scrolls, so keep the
list short enough to stay on one line at your widest breakpoint.

<TypeTable
  type={{
    logo: { type: 'upload', description: 'Brand mark from Media. Falls back to brandLabel when empty. Shared base field.' },
    brandLabel: { type: 'text', required: true, description: 'Accessible name for the brand, and the visible wordmark when no logo is set. Shared base field.' },
    copyright: { type: 'text', required: true, description: 'The copyright line below the rule. Shared base field.' },
    links: { type: 'array', required: true, description: 'One to eight links in a single flat row.' },
  }}
/>

Each item in `links` carries:

<TypeTable
  type={{
    label: { type: 'text', required: true, description: 'Visible link text.' },
    href: { type: 'text', required: true, description: 'Same-origin path, HTTPS URL, mailto:, or tel:. Anything else is rejected in the admin and skipped at render.' },
  }}
/>

## Usage

<ComponentUsage slug="footer-simple" />

Footer blocks render inside the Pages layout like every other block. To use one as site-wide chrome
instead, render the component directly in your root layout and pass it content from a global.
